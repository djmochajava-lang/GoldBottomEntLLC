## 3. Exact call shapes for the document path (reviewer: confirm against §3)

### 3a. Stage the document — matches §3a verbatim
```js
// onPickDoc(), after client-side validation
var key = 'bio-staging/' + _uid + '/doc-' + uuid() + '.' + ext;   // _uid = sb.auth.getSession().data.session.user.id
sb.storage.from('band-media').upload(key, file, { contentType: file.type, upsert: false })
```
- `_uid` is the member's Supabase `auth.uid()` (read from the PKCE session in `currentUid()`), so the key is `bio-staging/<auth.uid()>/doc-<uuid>.<ext>`.
- `uuid()` is `crypto.randomUUID()` (with a getRandomValues fallback).
- **Observed in test** (valid `.docx`): `bucket='band-media'`, `key='bio-staging/mock-uid-abc123/doc-aff58f11-…-…-….pdf'` (and `…​.docx`, `…​.txt`), `opts={ contentType:<file.type>, upsert:false }`. Uses the member's PKCE session — the exact client the image-staging path uses.

### 3b. Submit — additive keys on the SAME upsert (§3b)
```js
// doSubmit(): existing payload (text fields + images{}) is unchanged; then, only when a doc is staged:
if (hasDoc()){
  payload.document_staging_key = _doc.key;                                   // bucket-relative
  payload.document_meta = { filename: _doc.filename || '', ext: _doc.ext || '' };
}
sb.from('bio_submissions').upsert({ payload: payload, consent: consent, status: 'submitted' }, { onConflict: 'user_id' })
```
- **Observed (doc-only submit):** `table='bio_submissions'`, `onConflict='user_id'`, `status='submitted'`, `payload.document_staging_key='bio-staging/mock-uid-abc123/doc-…​.pdf'`, `payload.document_meta={filename:'resume.pdf',ext:'pdf'}`, `consent.version='bio-consent-v1_1-2026-07'`. `images{}` still present (existing shape preserved).
- **Observed (mixed submit):** the SAME upsert carried BOTH `payload.short_bio`/`stage_name` AND `document_staging_key`+`document_meta` on one row (requirement 4).
- `document_meta.filename`/`ext` are advisory (the server decides the real type by magic bytes and removes the staged object after extraction).

## 4. Client-side rejection (before any upload)

`onPickDoc` parses the extension from the filename and rejects **before** touching Storage:
- **`.doc`** → inline error **"Word 97–2003 (.doc) files aren't supported. Please save your file as .docx or PDF and upload again."** (mirrors the server `DOC_LEGACY_UNSUPPORTED` hint). 0 uploads attempted.
- Any non-`.txt`/`.docx`/`.pdf` → "Please upload a Word (.docx), PDF, or text (.txt) file." 0 uploads.
- **> 10 MB** (`DOC_MAX_BYTES`) → "Your file is too large. Please upload a file under 10 MB." 0 uploads.
- Upload failure (network / Storage error) → "Upload failed — please try again." + toast; Continue does NOT appear (no `_doc.key` set), so a failed upload can never reach submit.

**XSS:** every render of `_doc.filename` (upload view, "Document attached" note, submitted "Document shared" chip) is passed through the existing `esc()`/escapeHtml. Verified: a filename `my bio <img src=x>.pdf` renders as escaped text (`my bio &lt;img src=x&gt;.pdf`) with **no** raw `<img>` tag in the DOM.
